# Financial Transaction Analytics using Big Data (Windows, no Docker)
Synthetic CSV -> PySpark (clean, features, aggregations) -> MongoDB -> Streamlit dashboard, plus a Spark benchmark.

> **Data is SYNTHETIC** (generated by `src/generate_data.py`). It has no location fields, so there is no geographic analysis.
> **Spark runs in local mode** on one machine: work is split into partitions and processed by parallel threads (`local[*]` = all CPU cores).
> It is **not** a multi-node cluster. Same DataFrame code would run on a cluster by changing `SPARK_MASTER`.

## 1. Prerequisites (Windows)
1. **Python 3.10 or 3.11** (python.org, tick "Add to PATH"). Check: `python --version`
2. **Java JDK 17** (e.g. Eclipse Temurin). PySpark needs it. Check: `java -version`. If Spark can't find it, set `JAVA_HOME`.
3. **MongoDB Community Server** (mongodb.com/try/download/community), install as a Windows Service. Start it: `net start MongoDB` (Administrator terminal).
   Check: `mongosh` connects. *Alternative:* a free MongoDB Atlas cluster; put its URI in `.env`.
4. Hadoop/winutils is **not** needed (data is generated by NumPy and results are written by pymongo, not by Spark). Harmless "winutils" warnings from Spark can be ignored.

## 2. Setup
```
cd fin-bigdata
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```
(`run_project.bat setup` does the same.) Edit `.env` if MongoDB is not at `mongodb://localhost:27017/`.

## 3. 100K smoke test (do this first)
```
python src\generate_data.py --rows 100000
python src\pipeline.py
python src\benchmark.py --sizes 100000
streamlit run dashboard\dashboard.py
```
Or: `run_project.bat test`

## 4. Full experiment (up to 20M rows, ~2 GB)
Generate gradually; check disk space (~2 GB for 20M rows, plus benchmark subsets of about the same total again).
```
python src\generate_data.py --rows 1000000
python src\generate_data.py --rows 5000000
python src\generate_data.py --rows 20000000
python src\pipeline.py
python src\benchmark.py --sizes 100000,500000,1000000,5000000,10000000,20000000 --repeats 2
python src\benchmark.py --sizes 20000000 --cores 1,2,4        (optional: local thread comparison)
streamlit run dashboard\dashboard.py
```
Each `generate_data.py` run overwrites `data\transactions.csv`; benchmark sizes larger than the file are skipped with a message.
For 20M rows set `SPARK_DRIVER_MEMORY=6g` (or more, within your RAM) in `.env`. 4 GB data: `--rows 40000000`.
Benchmark times are measured, never hard-coded; they are saved to MongoDB `benchmark_results` and `output\benchmark_results.csv`.

## Files
| File | Purpose |
|---|---|
| `src/generate_data.py` | Chunked NumPy generator; fraud rules; ~0.1% injected nulls/negatives/duplicates |
| `src/common.py` | Config, schema, Spark session, `clean`, `features`, `analyze`, input checks |
| `src/pipeline.py` | Runs the Spark pipeline and writes MongoDB + `output\*.csv` |
| `src/benchmark.py` | Timed runs per dataset size (and optional local thread counts) |
| `src/mongodb_utils.py` | Mongo connection (env-configured) and save helpers |
| `dashboard/dashboard.py` | Streamlit dashboard with filters and Performance tab |
| `run_project.bat` | `setup`, `test`, `full`, `dashboard` shortcuts |

MongoDB collections (database `financial_analytics`): `transaction_summary`, `time_analysis` (day x hour x type), `amount_analysis`, `fraud_analysis`, `run_metadata`, `benchmark_results`. Only aggregates are stored, never raw rows.

## What is parallelized
`spark.read.csv` splits the file into partitions; filtering, feature columns, `groupBy` aggregations (with a shuffle across 16 partitions) run in parallel across threads. Results are small aggregate tables that are collected to the driver and written to MongoDB. Pandas is used only on those small tables (and chunk-wise in the generator).

## Limitations
- Single machine; speed-up is limited by cores, disk and RAM, and small datasets are dominated by Spark startup/overhead.
- Synthetic data: fraud patterns reflect the rules in the generator, so findings demonstrate the pipeline, not real-world fraud behaviour.
- "Day/hour" derive from `step` with an assumed start date of 2025-01-01.
